7. 横向对比

视觉重量轻：1 像素 bar + 反白焦点重：heavy border + chip + 块状指示

小屏 / compact 模式友好：留白多，borderless拥挤：双线 + chip 占用更多字符

8. 选哪个？

→ 选 A · Glass 如果...

  • 你希望 UI 安静、不抢戏，让 git / Claude 会话本身做主角
  • 你更在意可读性而不是"工程感"
  • 屏幕很小时（compact 布局）不希望被粗边框挤满
  • 你倾向 Linear / Things 这类线性工作流工具的克制美学

→ 选 B · Brutalism 如果...

  • 你希望远距离一眼看出"这个节点在跑、那个冲突了"
  • 你喜欢终端里"工作台"的密度感，能从 chip 一眼判读状态
  • 你愿意为视觉重量换更高的信息密度
  • 你想让 toast 像 CI dashboard 一样有进度条 / 状态徽章

10. 设计者自评

A · Glass 自我说明

节点图本质是一张由 Git DAG + worktree 状态共同驱动的并发会话图，节点之间的因果关系比"按钮"更重要——用户读屏时应能一眼扫到分支拓扑和当前 focus，而不是被边框和配色竞争注意力。#08090c 深底 + 单根 sky-300 焦点色把视觉重量压缩到一行 1 像素的 accent bar，left:-1 的位置让 bar 落在 panel 内部、不会与 padding 竞争，真正"free"出节点内容区；focus 整张反白借鉴了 Linear / Things 等线性工作流工具的"我正在操作这一个"语义，比传统虚线/粗框更克制。把 ─ │ ┐ ┘ └ ┌ ▶ 升级到 Unicode box-drawing 后边线成为单一连续的笔画，配合 amber 状态点和 sky 焦点色构成只有三档信息的图标语法，让并发的 Claude Code session 状态在任意 zoom 下都可读。

B · Brutalism 自我说明

Neobrutalist / high-contrast-terminal 美学契合并行 Claude Code session DAG 的两个原因：第一，单一 lime 高亮（#a3e635）+ 反白 focus 状态让 current worktree 和键盘焦点在任意缩放下都毫无歧义——工程师可以无脑定位"我在哪、这里在跑什么"，因为画布其余部分是刻意的黑/白/灰单色；第二，块状 ▰▰▱ 状态条 + [OK]/[RUN]/[FAIL]/[WAIT]/[DEL]/[SEAL] chip + heavy ━┃ border 让每个节点都有一眼可读的状态面，多个 Claude Code session 并发 commit 时能扫整张图立刻看出哪些 leaf 还在跑、哪些被 block、哪些已 seal；密集布局 + 高对比降低了在繁忙 terminal 中处理非平凡 DAG 的认知成本。Toast 顶部的进度条和 ▌ 描述前缀让 toaster 进一步变成"feed"，读起来像 CI dashboard，强化工程师工具氛围。
