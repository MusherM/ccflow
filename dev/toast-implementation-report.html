1. 设计与架构

toast 系统采用 核心 / 渲染 双层分离：核心是纯逻辑，可在没有 OpenTUI 的环境单测；渲染层是 OpenTUI 特定的薄壳，订阅核心快照后构造 OpenTUI 节点树。

src/core/toast.ts (pure logic, 0 渲染依赖) ┌────────────────────────────────────────────────────────────────┐ │ ToastEntry { id, type, message, description, duration, ... } │ │ ToastStore { add, update, dismiss, tick, list, onDismiss, ... }│ │ toastPromise(store, promise, { loading, success, error }) │ │ toastApi = Sonner-flavoured shortcuts (success/error/...) │ │ TOAST_DURATION = { SHORT, DEFAULT, LONG, EXTENDED, PERSISTENT }│ │ Default singleton store (resettable via __resetDefaultToastStore)│ └────────────────────────────────────────────────────────────────┘ │ list() / tick() ▼ src/tui/toast-actions.ts (TUI 适配, 0 渲染依赖) ┌────────────────────────────────────────────────────────────────┐ │ toastStore singleton + emitTuiToast / emitTuiErrorToast │ │ - loading 使用 persistent，成功/失败用同一 id 原地替换 │ │ - 保留 ui.message，同时补临时 toast 反馈 │ └────────────────────────────────────────────────────────────────┘ │ store ▼ src/tui/toast-overlay.ts (OpenTUI 渲染, 右上角) ┌────────────────────────────────────────────────────────────────┐ │ buildToasterOverlay(store, options) → BoxRenderable │ │ - position: "absolute", top: 1, right: 1, zIndex: 100 │ │ - 默认最多 5 条同时可见（oldest 截断） │ │ - 默认 maxWidth: 48 列 │ │ - 6 种 type 的图标 + 颜色 (success/error/warning/info/loading) │ │ - 空队列时渲染 0×0 占位，避免布局抖动 │ └────────────────────────────────────────────────────────────────┘ │ ▼ src/tui.ts:renderApp() (集成点, 已有) renderer.root.add(buildToasterOverlay(toastStore)) ← 每帧重建

1.1 关键设计决策

  • 无渲染依赖的核心：让 toast 可以在 200ms 内跑完所有单测，不依赖 PTY/OpenTUI 渲染线程。
  • tick 由调用方驱动：核心不内置 timer；TUI 的 renderApp 在每帧重建 toaster 时调用 store.tick()。这让测试可以注入 fake clock 精确控制时间。
  • 位置：右上角：通过 OpenTUI 的 position: "absolute" + top: 1, right: 1 实现。YAML 化的配置未来可以加 toast.position 选项。
  • 零新增依赖：完全基于已装的 @opentui/core@^0.2.14（Box / 绝对定位 / zIndex）。生态内的 @opentui-ui/toast 有 peer-dep 不兼容问题（要求 ^0.1.63），自研最干净。
  • toastApi 懒查询 singleton：__resetDefaultToastStore() 后 toastApi.list() 会反映重置后的状态，对测试隔离友好。

2.2 公共方法

API类型说明
toast(msg, opts?)function在默认 singleton store 上添加一条 default 类型的 toast，返回 id。
toast.success / .error / .warning / .info / .loadingfunction同上但预设 type，自动选用默认 duration。
toast.dismiss(id?)function省略 id 则清空所有；指定 id 则只清那条。
toast.promise(p, msgs)functionloading → success/error 三段联动，返回 { id, promise }。
toast.list()function当前快照（只读）。
toast.store()function拿到 ToastStore 实例，可订阅。
ToastStoreclass可独立实例化（用于多 store 场景、测试）。
toastApiconst同 toast，但与 __resetDefaultToastStore() 保持同步。
TOAST_DURATIONconstSHORT=2s / DEFAULT=4s / LONG=6s / EXTENDED=10s / PERSISTENT=∞
emitTuiToast(type, msg, opts?)functionTUI 适配入口，使用模块级 toastStore；传同一 id 可把 loading 原地替换为 success/error/warning。
emitTuiErrorToast(msg, error, id?)function把未知错误格式化到 description，默认使用 error 类型 LONG duration。
buildToasterOverlay(store, opts?)function渲染层入口，返回可挂到 renderer.root 的 OpenTUI Box。

2.3 用法示例

// 简单通知
toast.success(`Created sibling ${id}`);
toast.error("Merge conflict", { description: "3 files differ" });

// 异步联动
const handle = toast.promise(jobs.mergeLeaves(state, ids), {
  loading: "merging...",
  success: (m) => `Merge node ${m.id}`,
  error: (e) => e instanceof Error ? e.message : "merge failed",
});

// 手动 dismiss
toast.dismiss(handle.id);

// 多 store 场景（测试、隔离面板）
const custom = new ToastStore();
custom.add("hello");
custom.dismiss();

3.1 ToastStore API（核心）

class ToastStore {
  add(message: string, options?: { type?, id?, description?, duration?, action? }): string;
  update(id: string, patch: { type?, message?, description?, action?, duration? }): boolean;
  dismiss(id?: string): string[];            // 省略 id = 全部清空
  tick(): string[];                              // 推进时间，淘汰已过期
  list(): readonly ToastEntry[];                 // 快照
  size(): number;
  onDismiss(listener: (id: string) => void): () => void;
  onChange(listener: () => void): () => void;
}

type默认 duration理由

successDEFAULT (4s)成功消息一般可短读
errorLONG (6s)错误需更多阅读时间
warning / infoDEFAULT (4s)中性
loadingPERSISTENT (∞)由 toast.promise 主动 promote 或 toast.dismiss 手动关闭

  • add preserves insertion order
  • sequential loading -> success on the same id replaces the toast

update (6)

  • update on a missing id returns false and emits no change

  • update with action: null clears the action

dismiss (4)

  • dismiss with no id clears every entry and fires for each
  • dismiss on an empty store is a no-op
  • dismiss on an unknown id returns [] and fires no listener

tick (5)

  • tick on an empty store is a no-op
  • tick dismisses only the expired entries
  • tick fires dismiss listeners for expired toasts
  • tick that expires nothing fires no listeners
  • tick at exactly the expiry boundary dismisses the toast

listeners (4)

  • onDismiss listener can be unsubscribed
  • onChange fires on add, update, dismiss and tick-expiry but not on empty tick
  • onChange listener can be unsubscribed

toastPromise (4)

  • toastPromise promotes loading -> success on resolve
  • toastPromise promotes loading -> error on reject and rethrows
  • toastPromise supports description templates and string messages

6. 迁移策略

6.1 最小入侵

当前实现已经把 toastStore 单例和 buildToasterOverlay 集成到 renderApp，并完成 16 个赋值点的适配。改动没有替换 ui.message，只是在对应事件旁边补 toast；runAction 统一生成 loading toast，并由动作返回值或 catch 分支更新为最终状态。

6.2 本次落地范围

  1. 错误路径：runAction catch、不可编辑节点、merge 失败、打开 Codex/Claude 失败均发 error toast。
  2. 成功路径：创建 sibling/next、删除 leaf、切换 worktree、merge 成功、打开终端 tab、当前 tab 会话结束均发 success toast。
  3. 任务进度：runAction 和 merge 启动时发 loading toast；成功、失败或 conflict 时使用同一 id 更新。
  4. 信息提示：焦点 fallback 在 ui.message 为空时发 info toast。
  5. 测试与文档：新增 tests/tui-toast.test.ts；同步更新本报告与 AGENTS.md。

6.3 不变量与回归

  • 侧边面板 ui.message 必须保留，因为它是 Ready/任务当前状态的可见指示器，不能改成"已消失的弹窗"。
  • ui.task 字段：当前在 toolbar() 顶部条显示 "task: ..." 文字，迁移到 toast.loading 后是否要保留 ui.task？建议保留，作为 toolbar 的非弹层指示器（用户在多节点看图时浮层可能被遮挡）。
  • 测试要求：本次已通过 typecheck、测试编译、47 个 toast 相关单测、3 个非 Codex TUI smoke；发布前仍需跑完整 npm test 与 npm run test:coverage。
