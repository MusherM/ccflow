两条路径对比

默认

Current-tab 路径

入口：tui.ts:464 enterLeaf → enterLeafInCurrentTab。

关键调用：claude.attachOrResume(node, worktree.path, repoRoot, config)（src/core/claude.ts:35），内部用 spawnSync(claude, args, { stdio: "inherit" }) 同步执行到 claude 退出。

状态机：LeafRunning → claude.attachOrResume → LeafResumable（若发现 sessionId）/ LeafNew（无 sessionId）/ JobFailed（异常）。

进程模型：单进程同步，TUI 进程被 claude 阻塞；claude 退出后回到 TUI loop，runGraphOnce 重新创建 renderer。

终端清理：settle 内 renderer.suspend + destroy + resetTerminalForChildProcess + releaseStdinForChildProcess + drainTerminalInputBuffer；claude 退出后由 attachOrResume 的 finally 块做 quarantineTerminalInput（默认 800 ms，可由 claude.terminalQuarantineMs 或 CCFLOW_TERMINAL_QUARANTINE_MS 覆盖）。

opt-in

MultiTab 路径

入口：tui.ts:464 enterLeaf → enterLeafInTerminalTab → launchNodeSessionTab（src/core/node-session.ts:77）。

关键调用：openTerminalTab(request, { env, platform })（src/core/terminal-tabs.ts:122），按 detectTerminalApp 与 CCFLOW_TERMINAL_APP 强制值分发到 buildLaunchPlansForTerminal。

平台分发：macOS (Ghostty/iTerm2/Terminal.app 走 AppleScript)、Windows (wt new-tab)、Linux (wezterm cli spawn / kitty @ launch / gnome-terminal --tab / konsole --new-tab / xfce4-terminal --tab / alacritty/xterm 仅 window)。

进程模型：三进程协作，TUI 主进程 → osascript/wezterm/wt → 独立 tab 内跑 ccflow __node-session（src/cli.ts:230）→ runNodeSessionInCurrentTerminal（node-session.ts:146）→ claude.attachOrResume。

状态协调：.ccflow/sessions/<nodeId>.lock.json，pidIsAlive + pendingLockTtlMs（默认 30 s）。主 TUI 通过每 2 s reconcileNodeSessionState 轮询回灌 session 字段。

测试基础设施：OpenTUI preflight 根因与修复

在修复 H1 时发现 canRunOpenTuiRenderer()（tests/tui-smoke.test.ts:240）在 macOS 本机 永远返回 false，导致 5 个 TUI 用例（含用户写的真实 cc 测试）全部被 test.skip 兜底。CI workflow（.github/workflows/ci.yml）只跑 typecheck + pack:dry-run，从不跑 npm test，所以这个 bug 在仓库历史里从未被发现。

根因（6 次实测对比矩阵）

实验 deadline master drain bun 脚本结尾 耗时 exit status
A1 复现现状3s否r.destroy()3.2s143 (SIGTERM)
A2 加 drain3s是r.destroy()3.2s143 (SIGTERM)
A3 加 drain + 8s8s是r.destroy()8.6s143 (SIGTERM)
A4 加 drain + 20s20s是r.destroy()20.6s143 (SIGTERM)
A5 useThread:false + drain + 8s8s是r.destroy()8.6s143 (SIGTERM)
A6 关键修复8s是r.destroy(); process.exit(0);0.7s0

关键根因：OpenTUI 的 Zig render thread（useThread: true 默认）在 r.destroy() 后仍持有事件循环，bun 子进程不退出。Python preflight 死线到了就 SIGTERM（status 143）。useThread: false 单独不解决问题；process.exit(0) 才是唯一可靠的退出机制。

已排除的次要根因：

  • dylib 签名/quarantine：codesign -dv 显示 adhoc linker-signed，xattr -l 仅 com.apple.provenance，无 Gatekeeper 拦截。
  • bun 冷启动慢：非 PTY 环境下 bun -e 0.18s 完成，与 3s 死线无关。

修复内容（tests/tui-smoke.test.ts:240-294）

  • bun -e 脚本末尾追加 process.exit(0)（必加）
  • createCliRenderer 加 useThread: false（防御性，避免主线程退出时阻塞）
  • Python 内部死线 3s → 8s，参照 ptyDriverSource 范式加 master drain 循环
  • SIGTERM → 2s grace → SIGKILL 回收（参照 ptyDriverSource）
  • 外层 spawnSync timeout: 5000 → 15000
  • 失败时把 result.stdout / result.stderr 写到 process.stderr（可观测性）
