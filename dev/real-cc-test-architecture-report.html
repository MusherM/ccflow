真实 cc 测试分层与缓存设计报告

本报告说明这次改动如何在不 mock / fake 真实 Claude Code 流程的前提下，把测试分成“发送指令前”和“发送指令后”两层，并用 prompt 指纹避免每次都重跑昂贵的真实 cc / claude -p 测试。

目标与约束

日常快跑

提供 npm run test -- --skip-real-cc，开发时可以跳过所有真实 cc 测试。

默认省时

默认测试仍允许真实 cc 层运行，但 post-prompt 测试会按 prompt 指纹缓存，未变化时跳过。

发布兜底

提供 npm run test -- --force-real-cc，忽略缓存，强制刷新真实 cc 验证结果。

重要边界：涉及 Claude Code / cc 的测试仍然不使用 fake / stub / mock 替代真实 cc。缓存命中时是选择跳过已验证的真实层，而不是模拟它通过。

测试分层

层级 覆盖内容 是否昂贵 这次如何处理
发送指令前 配置加载、prompt 构造、graph / git / job runner 状态机、TUI 非真实 cc smoke、RecordingClaudeAdapter 验证调用参数。 低到中 每次照常运行，不走真实 cc 缓存。
发送指令后 真正调用 claude -p <prompt> 后，验证 cc 能把脏 worktree 提交干净，并产出真实 commit。 高 用 prompt SHA-256 指纹缓存；prompt 不变且之前通过时跳过。
交互式 cc 打开 TUI 按 Enter 后启动真实 Claude 交互进程。 高 --skip-real-cc 会跳过；它不属于 headless prompt post-prompt 缓存，因为没有稳定的 -p 指令文本。

入口设计

scripts/run-node-tests.mjs 现在负责解析测试参数，并把它们转换成测试进程内的环境变量。

npm run test
npm run test -- --skip-real-cc
npm run test -- --force-real-cc
参数 / 环境变量 含义
--skip-real-cc → CCFLOW_TEST_SKIP_REAL_CC=1 真实 cc helper 在探测 CLI 前直接抛出 skip 原因，因此不会启动或探测真实 Claude Code CLI。
--force-real-cc → CCFLOW_TEST_FORCE_REAL_CC=1 忽略已有缓存，post-prompt 真实 cc 测试必须重新运行，成功后覆盖缓存。
CCFLOW_TEST_REAL_CC_CACHE 缓存文件路径，runner 设置为项目内 .ccflow/test-cache/real-cc.json。

缓存流程

核心逻辑集中在 tests/helpers/claude-cli.ts 的 realClaudePromptGate(name, prompt)。

1
测试先构造即将发送给 Claude 的真实 prompt。这里使用 loadConfig({ repoRoot }).config、当前节点、git status 和 git diff，尽量和生产路径里的 prompt 完全一致。
2
realClaudePromptGate 对 prompt 做 sha256，得到 promptHash。
3
读取 .ccflow/test-cache/real-cc.json，按测试场景名查找上次通过的 promptHash。
4
如果 hash 一致且没有 --force-real-cc，测试调用 t.skip()，不再启动真实 claude -p。
5
如果 hash 不一致或没有缓存，测试继续真实运行 cc。断言全部通过后调用 gate.markPassed() 写入新的缓存 marker。
{
  "version": 1,
  "entries": {
    "job-runner.create-next.commit": {
      "promptHash": "…sha256…",
      "passedAt": "2026-06-03T..."
    },
    "tui-smoke.tab.commit": {
      "promptHash": "…sha256…",
      "passedAt": "2026-06-03T..."
    }
  }
}

已接入缓存的真实 cc 场景

缓存 key 测试文件 验证内容
job-runner.create-next.commit tests/job-runner.test.ts 直接从 JobRunner 路径触发真实 Claude Code 提交，验证父节点 sealed、worktree clean、commit 发生。
tui-smoke.tab.commit tests/tui-smoke.test.ts 从 TUI Tab 交互路径触发同类真实提交，验证 UI 到 job runner 的链路。
TUI Enter 打开交互 Claude 的测试会被 --skip-real-cc 跳过，但没有放进 prompt 指纹缓存，因为它不发送 headless prompt，缺少“指令内容没有变化”这个判断依据。

为什么 prompt 指纹稳定

真实 commit prompt 里包含节点信息、状态和 diff。为了避免“业务指令没变但测试随机值变了”导致缓存失效，这次对真实 cc 测试做了两点处理：

  • 真实 cc 测试使用稳定的 node_real_cc_commit / node_real_cc_tui_commit 这类测试 id。
  • 测试写入的 README 内容固定，因此 git diff 也稳定。

这样，只要 commit prompt 的内核、配置指导、测试输入 diff 没变，hash 就不会变化；一旦真实发送给 Claude 的指令发生变化，hash 会自然变化并触发重跑。

运行行为示例

命令 行为
npm run test -- --skip-real-cc 完整运行发送指令前层；真实 cc 测试显示 skipped。适合日常开发。
npm run test 没有缓存或 prompt 变化时运行真实 cc；缓存命中时跳过 post-prompt 真实 cc 场景。
npm run test -- --force-real-cc 强制真实运行并刷新缓存。适合发布前、修改 prompt kernel 后、怀疑缓存失真时。

验证情况

本次实现后运行：

npm run test -- --skip-real-cc

结果：201 tests，198 pass，3 skipped，0 fail。3 个 skipped 都是按参数跳过的真实 cc 测试。
